# Play Mode manual verification checklist — STEP 2 vertical slice

Этот чеклист используется **только если Unity Editor доступен человеку**, но автоматический
screenshot/Play Mode прогон в текущей среде невозможен. Он не заменяет реальную проверку:
пока он не пройден, пункты §3.3/§3.4 `REPORT.md` остаются «не проверено».

Target: Unity **2022.3.61f1**, Built-in Render Pipeline. Сцена: `Assets/Scenes/Game.unity`.

## 0. Подготовка (до нажатия Play)

1. `ProjectSettings/*.asset` уже сгенерированы Unity (см. `IMPLEMENTATION_ROADMAP.md` §5.1) —
   убедиться, что они на месте и файлы не удалены.
2. Открыть Unity 2022.3.61f1 → открыть папку проекта как существующий проект.
3. Дождаться импорта ассетов и компиляции скриптов. **Console должен быть без ошибок.**
   Записать полный Editor log (`~/Library/Logs/Unity/Editor.log` на macOS/Linux,
   `%LOCALAPPDATA%\Unity\Editor\Editor.log` на Windows).
4. В `File → Build Settings`: только `Assets/Scenes/Game.unity`, первая и включена.
5. Проверить `Window → Package Manager`: `com.unity.test-framework 1.1.33` и built-in
   модули `Particle System`, `Physics`, `Screen Capture` установлены (иначе CS1069,
   как в `prompt.txt` STEP 3). Console после компиляции — без ошибок.
6. Открыть сцену `Assets/Scenes/Game.unity`, нажать Play.

> Если на этом шаге есть compile error или сцена не стартует — останавливаемся и чиним
> именно её, не добавляя новые механики (STEP 3 §8).

**Скриншот 1 — Initial garage:** сделать после 1.1 (до нажатия «ИГРАТЬ»).

## 2. Визуальная проверка машины/камеры (до мойки)

| # | Проверка | Критерий |
|---|---|---|
| 2.1 | Машина видна в кадре целиком | Кузов, колёса, стёкла, дверные панели, арки, решётка не обрезаны камерой. |
| 2.2 | Пропорции | Седан читается как седан: длина > высоты, колёса на земле, кабина فوق кузова. |
| 2.3 | Гараж | Пол, стены, зона мойки, свет, реквизит присутствуют; нет «серых» неимпортированных материалов. |
| 2.4 | Камера | Клик по пустому месту +右 button/weel меняет orbit/zoom; машина остаётся в кадре. |

**Скриншот 2 — Vehicle before washing:** сделать после 2.1–2.3, до первого мазка.

## 3. Ввод и инструменты

| # | Действие | Ожидаемый результат |
|---|---|---|
| 3.1 | Навести на машину и зажать левую кнопку мыши, вести по кузову | Грязь исчезает вдоль траектории; прогресс-бар внизу растёт. |
| 3.2 | Попытаться нажать «ПЕНА» сразу | Кнопка неактивна/не переключает: пропуск этапа заблокирован. Активна только «СТРУЯ». |
| 3.3 | Завершить этап 1 (покойный кузов >= ~90% чистоты) | Автоматический переход к «Этап 2 из 6», активный инструмент «ПЕНА», подсказка «Покрой весь кузов пеной». |
| 3.4 | Вести пеногенератором по кузову | Появляется белая пена; прогресс растёт. |

**Скриншот 3 — Foam stage:** сделать в середине этапа 2, когда пена хорошо видна.

> На сенсорном устройстве повторить 3.1/3.4 касанием и перетаскиванием; UI не должен
> перехватывать касание, предназначенное для 3D-поверхности.

## 4. Полный шестиэтапный цикл

Пройти по порядку, каждый этап вести по кузову до завершения:

| Этап | Инструмент | Индикатор завершения |
|---|---|---|
| 1 | СТРУЯ | «Этап 2 из 6» |
| 2 | ПЕНА | «Этап 3 из 6» |
| 3 | ГУБКА | «Этап 4 из 6» |
| 4 | СМЫВ | «Этап 5 из 6» |
| 5 | СУШКА | «Этап 6 из 6» |
| 6 | ПОЛИРОВКА | запускается финал |

Каждое завершение должно давать звук `complete_task`, короткую подсказку
«Отлично! Готовим следующий этап…» и смену активной кнопки.

**Скриншот 4 — Final clean vehicle:** сделать сразу после этапа 6, до/в начале финала.

## 5. Финал 7+ секунд

| # | Проверка | Критерий |
|---|---|---|
| 5.1 | Световой блик проходит по кузову | Виден moving highlight (gloss sweep). |
| 5.2 | Появляются водитель и питомец | Procedural capsule/sphere figures рядом с машиной (placeholder art — это нормально). |
| 5.3 | Подсказка меняется | «Водитель и питомец радуются чистой машине!» → «Спасибо! Машинка снова блестит!». |
| 5.4 | Машина уезжает | Плавное движение вперёд с поворотом камеры; звук `engine`. |
| 5.5 | Тайминг | От начала финала до result screen — **не менее 7 секунд** (засечь по часам). Result screen НЕ появляется раньше. |

**Скриншот 5 — Celebration:** сделать на шаге 5.2/5.3.

## 7. Что делать при провале

- Записать точный шаг чеклиста, текст ошибки из Console и полный Editor log.
- Исправить только блокирующую проблему (STEP 3 §8), не расширяя функционал.
- Повторить чеклист с того же шага и отметить результат в `REPORT.md`.

Пока все 6 скриншотов и шаги 1–6 не пройдены, `REPORT.md` обязан содержать
«Play Mode: не проверено» — даже если код выглядит корректно.
